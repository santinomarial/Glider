# Support

Glider is a pre-1.0 project. Support is best effort; production deployment
requires the evidence described in the
[readiness contract](docs/release/production-readiness.md).

## Questions and bugs

Start with the [documentation index](docs/README.md) and
[local demo tutorial](docs/tutorials/local-demo.md). Search existing
[issues](https://github.com/santinomarial/Glider/issues), then open an issue
if the question or failure is not covered.

For bugs, provide the commit or version, operating system and architecture,
kernel and cgroup mode when relevant, exact commands, expected behavior, and
actual output. Include a minimal reproduction and redact secrets, credentials,
private hostnames, and identifying operator data.

Use feature requests to describe a concrete problem and the intended outcome.
No response-time guarantee applies to general support.

## Security reports

Do not disclose vulnerabilities in a public issue. Follow the private
reporting process and supported-version policy in [SECURITY.md](SECURITY.md).
